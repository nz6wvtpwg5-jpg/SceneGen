5. ABLY CHAT IMPLEMENTATION
================================================================================

From: src/components/chat/chat.tsx

Key Components:
- AblyProvider: Wraps the chat UI with Ably client context
- ChannelProvider: Provides access to specific conversation channel
- ChatBox: Renders messages and handles sending

Ably Client Setup:
const client = new Ably.Realtime({ authUrl: '/api' });

Authentication:
- Uses '/api' endpoint to authenticate with Ably
- Requires valid session with access_token

Channel Naming:
- Channel name = conversationId (from backend)
- Each conversation has its own channel

---

From: src/components/chat/chat-box.tsx

Message Flow:

1. RECEIVING MESSAGES:
   - Subscribe to channel via useChannel hook
   - Ably messages arrive in real-time
   - Messages formatted to ChatMessage interface
   - Stored in component state (last 200 messages)
   - Auto-scroll to bottom on new messages

2. SENDING MESSAGES:
   const messageData: AblyMessage = {
     name: 'chat-message',
     data: text,
     senderId: userId,
     timestamp: new Date().getTime()
   };
   channel.publish(messageData);

3. MESSAGE HISTORY:
   - Fetched on component mount
   - Endpoint: /api/messages?conversationId={channelId}
   - Sorted by timestamp (oldest first)
   - Merged with real-time messages

Features:
- User avatars generated per sender
- Auto-scroll to latest message
- Enter to send, Shift+Enter for new line
- Disabled send button when empty
- Loading state while fetching history
- Empty state message

6. API ROUTES FOR CHAT
================================================================================

A. GET /api/conversations
From: src/app/api/conversations/route.ts

Purpose: Fetch conversation history for current user

Authentication: Bearer token required

Backend Call:
- Uses conversation-client SDK
- Endpoint: postConversationhistory
- Payload: { pageSize: 10, continuationToken: "" }

Response:
{
  "conversations": [
    {
      "conversationId": "string",
      "lastMessage": "string",
      "updatedAt": "ISO 8601 date",
      "participants": ["name1", "name2"]
    }
  ],
  "continuationToken": "string"
}

---

B. GET /api/messages?conversationId={id}
From: src/app/api/messages/route.ts

Purpose: Fetch message history for a specific conversation

Parameters:
- conversationId (required): The conversation ID

Authentication: Bearer token required

Backend Call:
- Uses conversation-client SDK
- Endpoint: postMessagehistory
- Payload: { conversationId, pageSize: 50, continuationToken: "" }

Response:
{
  "messages": [
    {
      "messageId": "string",
      "conversationId": "string",
      "senderId": "string",
      "content": "string",
      "sentAt": "ISO 8601 date"
    }
  ]
}

---

C. POST /api (Ably Auth)
From: src/app/api/route.ts (assumed)

Purpose: Authenticate users with Ably for real-time chat

Returns: Ably token request for client authentication

8. KEY DIFFERENCES BETWEEN TYPES
================================================================================

Artist vs Promoter:
- Artists have "members" array (band members)
- Artists have "assets" array (media files)
- Promoters do NOT have members or assets
- Both share: administrators, users, location, bio

Frontend Entity vs Backend DTO:
- Frontend Entity is minimal (id, name, entityType, city, country)
- Backend DTO includes full details (administrators, members, assets, etc.)
- Frontend uses simplified Entity for UI/store
- Backend DTO used for API responses

Chat Message Types:
- ChatMessage: Frontend display format
- AblyMessage: Real-time message format
- Backend message format: Different structure with messageId, conversationId, sentAt

================================================================================
9. IMPORTANT NOTES
================================================================================

1. Entity IDs are GUIDs (UUID format)
2. All timestamps should use ISO 8601 format from backend
3. Frontend converts to Unix timestamps for display
4. Ably handles real-time messaging (WebSocket)
5. Backend uses Azure Functions + Cosmos DB
6. All API calls require Bearer token authentication
7. Subscription key required: Ocp-Apim-Subscription-Key
8. Conversation channels are named by conversationId
9. Messages limited to last 200 in memory (client-side)
10. Pagination supported via continuationToken

10. CURRENT FRONTEND USAGE PATTERNS
================================================================================

Entity Management:
- useProfileStore() to get/set active entity
- SidebarEntities component for entity switcher
- Entity dropdown shows all user's entities
- "Add Profile" button redirects to /onboarding

Chat Usage:
- Chat component wraps ChatBox with Ably providers
- ConversationList shows all conversations
- Clicking conversation loads ChatBox for that channel
- Messages fetch on mount, then real-time updates
- User avatars generated client-side (random-avatar-generator)

Onboarding Flow:
- New users redirected to /onboarding if no entities
- Choose Artist or Promoter
- Fill form with name, bio, location
- POST to /api/artist/add or /api/promoter/add
- Redirect to /dashboard after success
- Entities appear in sidebar immediately
