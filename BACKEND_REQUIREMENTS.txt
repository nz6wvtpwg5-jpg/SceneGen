## 📋 EXECUTIVE SUMMARY

The SceneGen frontend has completed 8 weeks of development and is production-ready. However, the following backend API endpoints are missing and need to be implemented for the application to function fully:

**Required Endpoints:**
- Shows API (7 endpoints)
- Tours API (7 endpoints)
- Invites API (3 endpoints)
- Enhanced Contacts API (1 endpoint)

**Estimated Backend Development Time:** 2-3 weeks
**Frontend Changes Required:** None (API contracts already defined)


**Business Logic:**
- Return shows where artistEntityId OR promoterEntityId matches user's entity

## 📊 DATABASE SCHEMA REQUIREMENTS

### Shows Table
```sql
CREATE TABLE shows (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  artist_entity_id UUID NOT NULL REFERENCES entities(id),
  promoter_entity_id UUID NOT NULL REFERENCES entities(id),
  venue_name VARCHAR(255) NOT NULL,
  venue_address VARCHAR(500),
  venue_city VARCHAR(100) NOT NULL,
  venue_state VARCHAR(100),
  venue_country VARCHAR(100) NOT NULL,
  venue_capacity INTEGER,
  latitude DECIMAL(10, 8),
  longitude DECIMAL(11, 8),
  date DATE NOT NULL,
  show_time TIME NOT NULL,
  doors_time TIME,
  set_length INTEGER,
  deal_type VARCHAR(50) NOT NULL CHECK (deal_type IN ('guarantee', 'door_split', 'flat_fee', 'versus_deal')),
  guarantee DECIMAL(10, 2),
  door_split DECIMAL(5, 2),
  ticket_price_low DECIMAL(10, 2),
  ticket_price_high DECIMAL(10, 2),
  contact_name VARCHAR(255),
  contact_phone VARCHAR(50),
  contact_email VARCHAR(255),
  notes TEXT,
  technical_requirements TEXT,
  tour_id UUID REFERENCES tours(id) ON DELETE SET NULL,
  status VARCHAR(50) NOT NULL DEFAULT 'draft' CHECK (status IN ('draft', 'pending_invite', 'pending_acceptance', 'confirmed', 'cancelled')),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  created_by UUID NOT NULL REFERENCES users(id),

  CONSTRAINT valid_date_check CHECK (date >= CURRENT_DATE),
  CONSTRAINT valid_capacity CHECK (venue_capacity IS NULL OR venue_capacity > 0),
  CONSTRAINT valid_guarantee CHECK (guarantee IS NULL OR guarantee >= 0),
  CONSTRAINT valid_door_split CHECK (door_split IS NULL OR (door_split >= 0 AND door_split <= 100))
);

CREATE INDEX idx_shows_artist ON shows(artist_entity_id);
CREATE INDEX idx_shows_promoter ON shows(promoter_entity_id);
CREATE INDEX idx_shows_tour ON shows(tour_id);
CREATE INDEX idx_shows_date ON shows(date);
CREATE INDEX idx_shows_status ON shows(status);
```

### Tours Table
```sql
CREATE TABLE tours (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  artist_entity_id UUID NOT NULL REFERENCES entities(id),
  name VARCHAR(255) NOT NULL,
  notes TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  created_by UUID NOT NULL REFERENCES users(id),

  CONSTRAINT unique_tour_name_per_artist UNIQUE (artist_entity_id, name)
);

CREATE INDEX idx_tours_artist ON tours(artist_entity_id);
```

### Invites Table
```sql
CREATE TABLE invites (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  token VARCHAR(255) NOT NULL UNIQUE,
  type VARCHAR(50) NOT NULL CHECK (type IN ('contact', 'show')),
  inviter_entity_id UUID NOT NULL REFERENCES entities(id),
  required_entity_type VARCHAR(50) CHECK (required_entity_type IN ('any', 'artist', 'promoter')),
  recipient_email VARCHAR(255),
  show_id UUID REFERENCES shows(id) ON DELETE CASCADE,
  status VARCHAR(50) NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'accepted', 'expired', 'cancelled')),
  expires_at TIMESTAMP WITH TIME ZONE NOT NULL,
  accepted_at TIMESTAMP WITH TIME ZONE,
  accepted_by UUID REFERENCES users(id),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),

  CONSTRAINT show_invite_requires_show CHECK (type != 'show' OR show_id IS NOT NULL)
);

CREATE INDEX idx_invites_token ON invites(token);
CREATE INDEX idx_invites_inviter ON invites(inviter_entity_id);
CREATE INDEX idx_invites_show ON invites(show_id);
CREATE INDEX idx_invites_expires ON invites(expires_at);
```

## 🔐 AUTHENTICATION & AUTHORIZATION

### Authentication
All endpoints (except GET /api/invites/{token}) require:
```
Authorization: Bearer {jwt_token}
Ocp-Apim-Subscription-Key: {subscription_key}
```

### Authorization Rules

#### Artist-Only Endpoints:
- POST /api/tours
- GET /api/tours
- GET /api/tours/{id}
- PATCH /api/tours/{id}
- DELETE /api/tours/{id}
- GET /api/contacts/promoters

**Return 403 Forbidden if user's entity is not an artist.**

#### Entity Ownership:
For shows:
- User must be either the artist OR promoter on the show
- Check: `user.entityId === show.artistEntityId OR user.entityId === show.promoterEntityId`

For tours:
- User must own the tour
- Check: `user.entityId === tour.artistEntityId`

For invites:
- User must be the inviter to view/cancel
- Check: `user.entityId === invite.inviterEntityId`

#### Trial Check (if applicable):
- Check `user.trialExpiresAt` on all POST/PATCH/DELETE operations
- Return 403 with message "Your trial has expired. Please upgrade." if expired

1. **Show Invitation Sent**
   - When: POST /api/shows with counterparty that doesn't have accepted contact
   - Recipient: Counterparty entity administrators
   - Message: "{Inviter} has invited you to a show on {date} at {venue}"

2. **Show Invitation Accepted**
   - When: POST /api/invites/{token}/accept (type=show)
   - Recipient: Show creator
   - Message: "{Accepter} has accepted your show invitation for {venue} on {date}"

3. **Show Details Changed**
   - When: PATCH /api/shows/{id} with date or venue changes
   - Recipient: Counterparty entity administrators
   - Message: "{Editor} has updated the show at {venue} on {date}"

4. **Show Cancelled**
   - When: DELETE /api/shows/{id}
   - Recipient: Counterparty entity administrators
   - Message: "{Canceller} has cancelled the show at {venue} on {date}"

5. **Contact Request via Invite**
   - When: POST /api/invites/{token}/accept (type=contact)
   - Recipient: Inviter entity administrators
   - Message: "{Accepter} has accepted your contact invitation"
