================================================================================
ROOT CAUSE ANALYSIS - CURRENT ISSUE
================================================================================

WHAT WENT WRONG:

The latest "fix" attempted to solve flickering by:
1. Positioning tooltip to the right of marker: pixelOffset(320, -200)
2. Adding hover delay logic with 150ms timeout
3. Wrapping tooltip in div with onMouseEnter/onMouseLeave

WHY IT FAILED:

1. EXTREME OFFSET POSITIONING
   - pixelOffset: new google.maps.Size(320, -200)
   - This pushes tooltip 320px to the right and 200px up
   - Creates massive spatial disconnect from marker
   - Tooltip appears nowhere near the waypoint it describes

2. MOUSE EVENT COORDINATION PROBLEM
   - Marker has: onMouseOver / onMouseOut
   - Tooltip div has: onMouseEnter / onMouseLeave
   - When tooltip is far from marker, mouse path doesn't cross both
   - Gap between marker and tooltip causes events to fire incorrectly
   - 150ms delay doesn't help when spatial distance is too large

3. FUNDAMENTAL DESIGN CONFLICT
   - InfoWindow is designed to appear AT or NEAR the marker position
   - Moving it far away breaks the mental model
   - User expects tooltip to appear at/near the hovered element
   - Current implementation violates this expectation

================================================================================
THE REAL PROBLEM - INFOWINDOW IS THE WRONG TOOL
================================================================================

GOOGLE MAPS INFOWINDOW LIMITATIONS:

InfoWindow is designed for:
- Click interactions (not hover)
- Single active window at a time
- Auto-positioning near markers
- Built-in close button
- Speech bubble appearance with arrow pointer

InfoWindow is NOT designed for:
- Hover tooltips that appear/disappear rapidly
- Custom positioning far from the target
- Preventing all default behaviors (pan, styling, positioning)
- Rapid state changes without flickering

EVIDENCE OF WRONG TOOL:
1. We've disabled most InfoWindow features (disableAutoPan, custom styling)
2. We're fighting against its default behaviors constantly
3. We've tried multiple positioning strategies, all problematic
4. The component keeps breaking when we override its design intent

================================================================================
WHY EACH ATTEMPTED FIX FAILED
================================================================================

ATTEMPT #1: Position Below Marker (pixelOffset: 0, 10)
Problem: When mouse moves from marker to tooltip below, it triggers onMouseOut
Result: Flickering loop - tooltip opens, mouse moves down, tooltip closes
Why it failed: Mouse path naturally crosses the boundary

ATTEMPT #2: Add Hover Delay + Position Far Right (pixelOffset: 320, -200)
Problem: Tooltip too far from marker, breaks user expectations
Result: Tooltip appears in wrong location, confusing UX
Why it failed: Excessive offset created spatial disconnect

ATTEMPT #3: Wrap Tooltip in Div with Mouse Events
Problem: Doesn't solve the fundamental InfoWindow positioning issue
Result: Events work on the div, but InfoWindow still controls positioning
Why it failed: We're mixing InfoWindow behavior with custom event handling

================================================================================
THE CORRECT SOLUTION - CUSTOM OVERLAY
================================================================================

WHAT WE SHOULD USE INSTEAD:

Use a Custom Google Maps Overlay (OverlayView) instead of InfoWindow.

WHY THIS IS THE RIGHT APPROACH:

1. FULL CONTROL OVER POSITIONING
   - Can position tooltip exactly where we want
   - Can adjust based on viewport boundaries
   - Can position relative to marker in any direction
   - No fighting against default behaviors

2. FULL CONTROL OVER STYLING
   - Pure React/HTML/CSS component
   - No Google Maps default styling to override
   - No white backgrounds or speech bubble arrows
   - Complete design freedom

3. FULL CONTROL OVER EVENTS
   - Standard React onMouseEnter/onMouseLeave
   - No conflicts with marker events
   - Can implement proper hover logic
   - No flickering from event coordination issues

4. DESIGNED FOR HOVER TOOLTIPS
   - OverlayView is meant for custom overlays
   - Perfect for tooltips, labels, custom markers
   - Handles viewport bounds automatically (with custom logic)
   - Doesn't fight against its design purpose

STEP 3: Smart Positioning Logic
--------------------------------
Algorithm:
1. Get marker screen position
2. Get tooltip dimensions (300px width, ~350px height)
3. Check available space in all 4 directions
4. Choose position with most space
5. Default to above marker if space is equal
6. Add appropriate offset (20-40px from marker)

Priority order:
- Above marker (preferred)
- Right of marker
- Left of marker
- Below marker (last resort)

STEP 4: Hover Behavior
----------------------
1. Marker onMouseOver → Create overlay instance
2. Marker onMouseOut → Start 200ms delay
3. Tooltip onMouseEnter → Cancel delay, keep overlay
4. Tooltip onMouseLeave → Destroy overlay immediately

This prevents flickering because:
- Overlay is a true HTML element
- Standard mouse events work correctly
- No Google Maps event conflicts
- Proper event bubbling and timing

ALTERNATIVE SOLUTION - SIMPLE HTML TOOLTIP
================================================================================

EVEN SIMPLER APPROACH:

Instead of Google Maps Overlay, use pure HTML/CSS tooltip positioned with
React Portals.

IMPLEMENTATION:

1. On marker hover, get marker's screen coordinates
2. Convert to viewport pixels using map.getProjection()
3. Render tooltip as absolute-positioned div
4. Use React Portal to render outside map container
5. Position relative to viewport, not map

ADVANTAGES:
- Simpler than OverlayView
- Standard React patterns
- No Google Maps API complexity
- Easy to test and debug

DISADVANTAGES:
- Need to handle map pan/zoom events
- Need to update position when map moves
- More manual coordinate conversion
