GOOGLE PLACES AUTOCOMPLETE ISSUE IN MODAL - COMPREHENSIVE TECHNICAL REPORT
================================================================================

DATE: Updated December 2024
FILE: /src/app/import/components/TourOriginDestinationModal.tsx
COMPONENT: PlacesAutocomplete from @/components/maps/PlacesAutocomplete.tsx
FRAMEWORK: Next.js 15.2.1 with React Server/Client Components
UI LIBRARY: Radix UI (@radix-ui/react-dialog v1.1.15)

ISSUE SUMMARY:
Google Places Autocomplete dropdown selection works perfectly in regular pages but FAILS when used inside a Radix UI Dialog/Modal component. When a user clicks on a suggestion in the dropdown with a mouse, nothing happens - the selection is not captured. However, keyboard selection (typing and pressing Enter/Arrow keys) DOES work.

ROOT CAUSE:
The Radix UI Dialog component implements aggressive focus trapping which intercepts events from elements outside the modal's DOM tree. Google Places Autocomplete renders its dropdown (.pac-container) as a direct child of document.body (outside the modal's React tree), causing event conflicts.

TECHNICAL ARCHITECTURE:
================================================================================

1. DIALOG COMPONENT (Radix UI):
   File: /src/components/ui/dialog.tsx
   Library: @radix-ui/react-dialog v1.1.15

   Focus Trap Mechanism:
   - Radix Dialog uses @radix-ui/react-focus-scope internally
   - Implements "focus containment" to keep focus inside the modal
   - Prevents clicks/focus on elements outside the modal's DOM tree
   - Uses event.preventDefault() on mousedown events for external elements

   DOM Structure:
   ```
   <body>
     <div id="__next">...</div>
     <DialogPortal>
       <DialogOverlay /> (z-index: 50, backdrop)
       <DialogContent> (z-index: 50)
         <TourOriginDestinationModal>
           <PlacesAutocomplete>
             <Input /> ← Inside modal tree
           </PlacesAutocomplete>
         </TourOriginDestinationModal>
       </DialogContent>
     </DialogPortal>
     <div class="pac-container"> ← OUTSIDE modal tree!
       <div class="pac-item">Atlanta, GA</div>
     </div>
   </body>
   ```

2. GOOGLE PLACES AUTOCOMPLETE:
   Library: @react-google-maps/api (wraps Google Maps JavaScript API)

   Event Flow:
   a. User types in <Input> → Google API creates .pac-container in document.body
   b. User clicks .pac-item → Google API should fire 'place_changed' event
   c. @react-google-maps/api Autocomplete listens for 'place_changed' via onPlaceChanged prop
   d. onPlaceChanged callback extracts place data and calls parent's onChange

   PROBLEM: Step (b) is intercepted by Radix Dialog's focus trap:
   - Radix detects mousedown on .pac-item (outside modal tree)
   - Radix calls event.preventDefault() to maintain focus trap
   - Input receives blur event BEFORE Google can fire 'place_changed'
   - Result: onPlaceChanged never executes

   File: /src/app/import/components/Step3Validation.tsx (lines ~1130)
   Context: Regular page (NOT in a modal)
   Status: ✅ WORKS PERFECTLY

   Why it works:
   - No Dialog wrapper, no focus trap
   - .pac-container events propagate normally
   - Google's 'place_changed' fires reliably on click

4. BROKEN IMPLEMENTATION:
   File: /src/app/import/components/TourOriginDestinationModal.tsx
   Context: Inside Radix UI Dialog
   Status: ❌ MOUSE CLICKS FAIL, ✅ KEYBOARD WORKS

Dependencies:

Component Structure:
```tsx
export function PlacesAutocomplete({ value, onChange, placeholder, label, error }) {
  const { isLoaded } = useLoadScript({
    googleMapsApiKey: process.env.NEXT_PUBLIC_GOOGLE_MAPS_API_KEY,
    libraries: ["places"],
  });

  const [autocomplete, setAutocomplete] = useState(null);
  const [inputValue, setInputValue] = useState(value);

  const onLoad = (autocompleteInstance) => {
    setAutocomplete(autocompleteInstance);
  };

  const onPlaceChanged = () => {
    if (autocomplete) {
      const place = autocomplete.getPlace();
      if (place.geometry && place.geometry.location) {
        const address = place.formatted_address || '';
        const lat = place.geometry.location.lat();
        const lng = place.geometry.location.lng();

        // Extract city and state from address_components
        let city = '';
        let state = '';
        if (place.address_components) {
          for (const component of place.address_components) {
            if (component.types.includes('locality')) {
              city = component.long_name;
            }
            if (component.types.includes('administrative_area_level_1')) {
              state = component.short_name;
            }
          }
        }

        setInputValue(address);
        onChange(address, lat, lng, name, city, state);
      }
    }
  };

  return (
    <div className="space-y-2">
      {label && <Label>{label}</Label>}
      <Autocomplete onLoad={onLoad} onPlaceChanged={onPlaceChanged}>
        <Input
          type="text"
          placeholder={placeholder}
          value={inputValue}
          onChange={(e) => setInputValue(e.target.value)}
        />
      </Autocomplete>
    </div>
  );
}
```

onChange Signature:
```tsx

  address: string,
  lat: number,
  lng: number,
  name?: string,
  city?: string,
  state?: string
) => void
```

SOLUTION 1: Disable Radix Dialog Focus Trap for .pac-container ⭐⭐⭐⭐⭐ (RECOMMENDED)
----------------------------------------------------------------------------------
Modify the Dialog component to exclude .pac-container from focus trapping.

Implementation:
```tsx
// In /src/components/ui/dialog.tsx
const DialogContent = React.forwardRef<...>(({ className, children, ...props }, ref) => (
  <DialogPortal>
    <DialogOverlay />
    <DialogPrimitive.Content
      ref={ref}
      onInteractOutside={(event) => {
        // Allow clicks on Google Places dropdown
        const target = event.target as HTMLElement;
        if (target.closest('.pac-container')) {
          event.preventDefault();
        }
      }}
      // ... rest of props
    >
      {children}
    </DialogPrimitive.Content>
  </DialogPortal>
));
```

Pros:
✅ Minimal code change (one event handler)
✅ Maintains modal functionality
✅ Works with existing PlacesAutocomplete component
✅ No need to fork or replace Radix Dialog

Cons:
⚠️ Allows clicks outside modal on .pac-container only
⚠️ Must test that modal still traps focus for other elements

Testing Plan:
1. Verify mouse clicks on .pac-item work
2. Verify clicks outside modal (not .pac-container) still close modal
3. Verify keyboard Tab navigation stays inside modal

SOLUTION 3: Replace @react-google-maps/api with Google Places Autocomplete Service ⭐⭐⭐
----------------------------------------------------------------------------------
Use Google's lower-level Autocomplete Service API to render a custom dropdown inside the modal's DOM tree.

Implementation:
```tsx
// Create new component: /components/maps/PlacesAutocompleteService.tsx
import { AutocompleteService, PlacesService } from '@react-google-maps/api';

export function PlacesAutocompleteService({ value, onChange }) {
  const [predictions, setPredictions] = useState([]);
  const autocompleteService = new google.maps.places.AutocompleteService();

  const handleInputChange = (input: string) => {
    autocompleteService.getPlacePredictions(
      { input, componentRestrictions: { country: 'us' } },
      (results) => setPredictions(results || [])
    );
  };

  const handleSelect = (placeId: string) => {
    const placesService = new google.maps.places.PlacesService(...);
    placesService.getDetails({ placeId }, (place) => {
      onChange(place.formatted_address, lat, lng, ...);
    });
  };

  return (
    <div className="relative">
      <Input value={value} onChange={(e) => handleInputChange(e.target.value)} />
      {predictions.length > 0 && (
        <div className="absolute z-50 bg-white border shadow-lg"> {/* Inside modal DOM */}
          {predictions.map((prediction) => (
            <div key={prediction.place_id} onClick={() => handleSelect(prediction.place_id)}>
              {prediction.description}
            </div>
          ))}
        </div>
      )}
    </div>
  );
}
```

Pros:
✅ Dropdown stays inside modal's DOM tree (no focus trap conflict)
✅ Full control over UI/UX
✅ No Radix Dialog modifications needed

Cons:
❌ Significant development time (2-4 hours)
❌ Requires reimplementing keyboard navigation (Up/Down/Enter)
❌ Must handle styling to match Google's default dropdown
❌ More code to maintain
