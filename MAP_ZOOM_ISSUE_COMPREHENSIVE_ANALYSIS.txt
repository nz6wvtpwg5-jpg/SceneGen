================================================================================
ROOT CAUSE ANALYSIS
================================================================================

PRIMARY SUSPECT: DirectionsRenderer Viewport Override

The most likely cause is that the Google Maps DirectionsRenderer component
automatically adjusts the viewport to fit the calculated route, and this
happens AFTER our custom fitBounds() calls.

Evidence:
1. fitBounds is confirmed to be called with correct parameters
2. The issue only manifests after the route is rendered
3. DirectionsRenderer has built-in viewport adjustment behavior
4. This is a known behavior pattern in Google Maps API

Timeline of Events:
1. Map loads → onLoad callback fires → fitBounds() called → viewport set
2. Route calculation begins → DirectionsService calculates route
3. DirectionsRenderer receives route → automatically adjusts viewport
4. Custom viewport from fitBounds() is overridden
5. Result: Map zooms to DirectionsRenderer's preferred viewport

================================================================================
PROPOSED SOLUTIONS
================================================================================

SOLUTION 1: Use preserveViewport Option (RECOMMENDED)
------------------------------------------------------
Priority: HIGH
Difficulty: LOW
Expected Success Rate: 90%

Implementation:
- Add preserveViewport={true} to DirectionsRenderer component
- This tells DirectionsRenderer not to adjust the viewport automatically
- Our custom fitBounds() calls will then maintain control

Code Change Required:
<DirectionsRenderer
  directions={route}
  options={{
    polylineOptions: {
      strokeColor: '#4F46E5',
      strokeWeight: 4,
      strokeOpacity: 0.8,
    },
    suppressMarkers: true,
    preserveViewport: true,  // ADD THIS LINE
  }}
/>

Pros:
+ Simple one-line change
+ Documented solution for this exact problem
+ Maintains our custom viewport control
+ No side effects expected

Cons:
- If fitBounds isn't working for another reason, this won't help
- Requires testing to confirm it resolves the issue


SOLUTION 2: Re-apply fitBounds After Route Render
--------------------------------------------------
Priority: MEDIUM
Difficulty: MEDIUM
Expected Success Rate: 70%

Implementation:
- Call fitBounds() again after DirectionsRenderer has finished rendering
- Use a small delay (100-200ms) to ensure DirectionsRenderer has completed
- This would override DirectionsRenderer's viewport adjustment

Code Pattern:
useEffect(() => {
  if (route && mapRef.current) {
    setTimeout(() => {
      mapRef.current?.fitBounds(bounds, padding);
    }, 200);
  }
}, [route]);

Pros:
+ Works even if DirectionsRenderer changes viewport
+ Gives us final control over the viewport

Cons:
- Requires timing/delay which is not ideal
- May cause visible "jump" in the viewport
- Less elegant than preserveViewport option


SOLUTION 3: Custom Route Rendering
-----------------------------------
Priority: LOW
Difficulty: HIGH
Expected Success Rate: 95%

Implementation:
- Don't use DirectionsRenderer at all
- Use DirectionsService to get route data
- Manually render the route using Polyline component
- Full control over viewport at all times

Pros:
+ Complete control over rendering and viewport
+ No conflicts with built-in behaviors
+ Most flexible solution

Cons:
- Significant refactoring required
- More code to maintain
- Would need to manually handle all route visualization
- Time-intensive implementation
