2. ROOT CAUSE ANALYSIS
================================================================================

INITIAL PROBLEM (RESOLVED):
- Coordinates were stored as strings in the database
- Frontend expected numeric lat/lng values
- Type mismatch prevented proper coordinate processing

CURRENT PROBLEM (ACTIVE):
- Google Directions API returns "REQUEST_DENIED" error
- This is a Google Cloud Platform configuration issue
- API key, quota, or project settings are blocking requests

POSSIBLE CAUSES:
1. API key restrictions (HTTP referrer, IP address, API restrictions)
2. Directions API not enabled in Google Cloud Console
3. Billing not properly configured
4. API quota exceeded
5. API key not fully propagated (can take 5+ minutes)
6. API key tied to wrong Google Cloud project
7. API key missing necessary scopes/permissions

5. REMAINING PROBLEM
================================================================================

GOOGLE CLOUD CONSOLE CONFIGURATION ISSUE

The Directions API is rejecting requests despite:
- Valid API key
- Numeric coordinates
- Proper request format
- API enabled in console
- Billing enabled

MOST LIKELY CAUSES (in order of probability):

1. API KEY RESTRICTIONS
   - HTTP referrer restrictions blocking localhost
   - IP address restrictions
   - API restrictions limiting which APIs can be called

2. PROPAGATION DELAY
   - Recently created/modified API key
   - Changes can take 5-10 minutes to propagate

3. BILLING ISSUES
   - Free trial expired
   - Payment method declined
   - Spending limits reached

4. PROJECT CONFIGURATION
   - API key tied to wrong project
   - Directions API not enabled in correct project
   - Quota limits set too low

6. STEP-BY-STEP TROUBLESHOOTING
================================================================================

STEP 1: VERIFY DIRECTIONS API IS ENABLED
-----------------------------------------
1. Go to: https://console.cloud.google.com/apis/library
2. Search for "Directions API"
3. Ensure it shows "API ENABLED" (not "ENABLE" button)
4. Click "MANAGE" and check quotas:
   - Queries per day should be > 0
   - Queries per 100 seconds should be > 0
5. If not enabled, click "ENABLE" and wait 5 minutes

STEP 2: CHECK API KEY RESTRICTIONS
-----------------------------------
1. Go to: https://console.cloud.google.com/apis/credentials
2. Find your API key and click to edit
3. Under "Application restrictions":
   - Set to "None" for testing (INSECURE - temporary only)
   - OR set to "HTTP referrers" with: http://localhost:*
4. Under "API restrictions":
   - Set to "Don't restrict key" for testing
   - OR ensure "Directions API" is in the allowed list
5. Save changes and wait 5-10 minutes for propagation

STEP 3: VERIFY BILLING
-----------------------
1. Go to: https://console.cloud.google.com/billing
2. Ensure billing account is linked to your project
3. Check that payment method is valid
4. Verify no spending limits are blocking API calls
5. Check billing alerts for any warnings

STEP 4: CHECK QUOTAS
---------------------
1. Go to: https://console.cloud.google.com/apis/api/directions-backend.googleapis.com/quotas
2. Verify "Queries per day" is not 0 or exhausted
3. Check "Queries per 100 seconds" limit
4. If quotas are low, request an increase
5. Check quota usage graph for any spikes

STEP 5: TEST API KEY DIRECTLY
------------------------------
1. Open a new browser tab
2. Paste this URL (replace YOUR_API_KEY):

https://maps.googleapis.com/maps/api/directions/json?origin=37.7749,-122.4194&destination=34.0522,-118.2437&key=YOUR_API_KEY

3. Expected response: JSON with "status": "OK" and routes
4. If error, note the exact error message
5. Common errors:
   - REQUEST_DENIED: API key or billing issue
   - OVER_QUERY_LIMIT: Quota exceeded
   - INVALID_REQUEST: Malformed parameters

STEP 6: CREATE NEW API KEY (if needed)
---------------------------------------
1. Go to: https://console.cloud.google.com/apis/credentials
2. Click "+ CREATE CREDENTIALS" → "API Key"
3. Copy the new key immediately
4. Edit restrictions:
   - Application restrictions: None (for testing)
   - API restrictions: None (for testing)
5. Update .env.local with new key:
   NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=your_new_key_here
6. Restart the frontend server
7. Wait 5-10 minutes for propagation
8. Test again

STEP 7: VERIFY ENVIRONMENT VARIABLE
------------------------------------
1. Check .env.local file exists in project root
2. Verify this exact line (no typos):
   NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=your_actual_key
3. No quotes, spaces, or special characters
4. Restart Next.js dev server: npm run dev
5. Check browser console for the API key being loaded

STEP 8: CHECK BROWSER CONSOLE
------------------------------
1. Open browser DevTools (F12 or Cmd+Option+I)
2. Go to Console tab
3. Filter for "Google" or "Maps"
4. Look for error messages with details
5. Check Network tab for failed API requests
6. Look for red 403/400 errors to Directions API

```typescript
export function convertShowForMap(show: Show): MapLocation {
  return {
    id: show.id,
    name: show.venueName || 'Unknown Venue',
    lat: Number(show.venueLat),
    lng: Number(show.venueLng),
    date: show.date,
    city: show.city || '',
    state: show.state || '',
  };
}

export function hasValidCoordinates(location: MapLocation): boolean {
  return (
    typeof location.lat === 'number' &&
    typeof location.lng === 'number' &&
    !isNaN(location.lat) &&
    !isNaN(location.lng) &&
    location.lat !== 0 &&
    location.lng !== 0 &&
    location.lat >= -90 &&
    location.lat <= 90 &&
    location.lng >= -180 &&
    location.lng <= 180
  );
}
```

10. ALTERNATIVE SOLUTIONS
================================================================================

OPTION A: POLYLINE FALLBACK (SIMPLE)
-------------------------------------
If Directions API continues to fail, draw straight lines:

PROS:
- No API quota usage
- Always works
- Fast rendering
- No billing required

CONS:
- Lines don't follow roads
- Distance is "as the crow flies"
- Less accurate for road trips
- Less professional appearance

IMPLEMENTATION:
Add to TourMap.tsx after Directions API error:

```typescript
// Fallback: Draw straight lines
const path = locations.map(loc => ({
  lat: loc.lat,
  lng: loc.lng
}));

const polyline = new google.maps.Polyline({
  path: path,
  geodesic: true,
  strokeColor: '#3B82F6',
  strokeOpacity: 1.0,
  strokeWeight: 3,
  map: map
});

// Calculate distance using Haversine formula
const totalDistance = calculateHaversineDistance(locations);
```

OPTION B: DISTANCE MATRIX API
------------------------------
Alternative to Directions API for distances:

PROS:
- May have different quota limits
- Provides travel times
- Multiple origin/destination support

CONS:
- Doesn't provide route polylines
- Still requires Google Cloud billing
- May have same restriction issues

OPTION C: THIRD-PARTY ROUTING
------------------------------
Use alternative mapping services:

OPTIONS:
- Mapbox Directions API
- HERE Maps API
- OpenRouteService (open source)
- OSRM (Open Source Routing Machine)

PROS:
- Different billing/quota structure
- May be more cost-effective
- Some have free tiers

CONS:
- Requires new API setup
- Different integration code
- May require migration from Google Maps

================================================================================
QUICK REFERENCE: COMMON ERROR CODES
================================================================================

REQUEST_DENIED
- API key missing or invalid
- API not enabled
- Billing not configured
- API restrictions blocking request

OVER_QUERY_LIMIT
- Daily quota exceeded
- Rate limit exceeded
- Need to increase quotas

INVALID_REQUEST
- Malformed parameters
- Missing origin/destination
- Invalid coordinates

ZERO_RESULTS
- No route found between points
- Points too far apart
- Points in invalid locations

UNKNOWN_ERROR
- Server-side issue
- Retry the request
- Check Google Cloud Status Dashboard
